## Career Direction Comparison

Based on my research, I identified two career directions: Networking and Network Administration, and Technical Support and IT Infrastructure.

| Category | Networking and Network Administration | Technical Support and IT Infrastructure |
|---|---|---|
| Employer evidence | S1 | S2, S3 |
| Entry-level positions | Network Aide, Network Technician, NOC Technician | Technical Support Specialist, IT Support Analyst |
| Responsibilities | Maintain network infrastructure and troubleshoot connectivity issues | Troubleshoot hardware, software, servers, and infrastructure |
| Technical skills | TCP/IP, DNS, DHCP, routing, switching, firewalls | Linux, Windows, virtualization, networking, cloud infrastructure |
| Existing experience | Networking coursework, firewall configuration, port forwarding | Linux, virtual machines, Docker, Apache, systems integration |
| Skills to develop | VLANs, subnetting, Cisco equipment, structured cabling | Active Directory, ticketing systems, monitoring, automation |
| Career progression | Network Administrator, Network Engineer | Systems Administrator, Cloud Engineer |

Both career directions require technical troubleshooting, networking fundamentals, communication, and documentation. However, networking positions focus more heavily on communication between devices, while technical support and infrastructure positions involve a wider range of hardware, software, and system-related responsibilities.

I selected Technical Support and IT Infrastructure as my primary career direction because it allows me to apply a wider range of my existing technical skills while continuing to develop my networking knowledge.

## Portfolio Layout Comparison

### Layout 1: Single-Page Portfolio

A single-page portfolio would organize my introduction, background, skills, projects, and contact information on one webpage.

This approach would be relatively simple to develop and would allow recruiters to quickly review my qualifications. However, including detailed technical documentation and multiple project descriptions could make the page lengthy and difficult to navigate.

### Layout 2: Multi-Page Portfolio

A multi-page portfolio would separate my background, skills, projects, and contact information into individual pages. Featured projects could also have dedicated pages containing technical explanations, architecture diagrams, and supporting evidence.

This approach requires more development and maintenance but provides a more organized way to present detailed technical projects.

| Criterion | Single-Page | Multi-Page |
|---|---|---|
| Development complexity | Low | Moderate |
| Quick overview | Excellent | Good |
| Detailed project documentation | Limited | Excellent |
| Navigation | Scrolling and section links | Separate pages |
| Future expansion | Limited | More flexible |
| Maintenance | Simple | Requires additional organization |

### Selected Layout

I selected a lightweight multi-page portfolio because my technical projects would benefit from dedicated pages that explain their architecture, technologies, and individual contributions.

The homepage will provide a concise overview of my qualifications, while the project pages will allow technical hiring managers to examine my work in more detail.

I plan to use HTML, CSS, and JavaScript to develop the portfolio, GitHub for version control, and GitHub Pages as the proposed hosting platform. A static website is sufficient because the portfolio does not require complex backend functionality.
